# 행동특성 및 종합의견 자동 작성 — CLAUDE.md

## 0. 프로젝트 개요
구글 스프레드시트에 기록된 학생별 활동 이력(1학기·2학기)을 읽어,
학생 개인별 "행동특성 및 종합의견" 문구를 자동 생성한다.
- 월별로 별도 세션을 실행하며, 각 세션은 해당 월 자료만 다루고 이전 달 원자료는 다시 불러오지 않는다.
- 12월 초에는 그동안 누적된 자료를 모두 합쳐 최종 종합의견을 작성한다.
- 저장 전 반드시 사용자 승인을 받으며, 사용자가 정확히 "승인함"이라고 답하기 전에는 세션을 종료하지 않는다.

**⚠️ 중요 — 개인정보 보호**
두 문서 모두 대상 탭 외에 학생 개인정보(휴대폰 번호, 자택 주소, 부모 연락처 등)와 수행평가 점수, 진도표 등 이 프로젝트와 무관한 다른 탭들이 같은 문서 안에 함께 들어 있음을 확인함. Claude Code는:
- 반드시 위 표에 명시된 탭만 읽어야 하며, 같은 문서 내 다른 탭(개인정보, 성적, 진도 등)은 절대 열람·처리·인용하지 않는다.
- 생성되는 문구·보고서·저장 파일 어디에도 연락처, 주소 등 개인정보가 포함되지 않도록 한다.
- 문서 전체를 한 번에 읽는 방식(예: 파일 전체 텍스트 추출)을 쓰면 다른 탭 내용까지 함께 딸려 올 수 있으므로, 대상 탭만 선택적으로 읽는 방법을 우선 사용한다.

## 2. 자료 구분 규칙 (실제 확인된 내용)

### 2학기 — 이미 텍스트 접두문자로 구분되어 있음
2학기 탭은 Apps Script가 셀 배경색을 입힘과 **동시에 셀 텍스트 앞에 구분 기호를 자동으로 붙여둔 상태**임 (시트 하단 범례 행에서 확인):
| 접두기호 | 색상(참고용) | 의미 |
|---|---|---|
| `ㄷ` | 노랑 | 대회 참가/수상 이력 |
| `ㅇ` | 청록 | 학급에서의 역할 |
| `ㅌ` | 민트 | 가정통신문 제출(도서 관련 통신문 포함) — 텍스트에 "독서로"가 포함되어 있으면 그 달의 독서록 작성 이력, 포함되어 있지 않으면 일반 가정통신문 제출로 구분 |
| `ㅈ` | 빨강 | 지적 사항 |

→ 따라서 2학기는 **셀 배경색을 읽을 필요 없이, 각 셀 텍스트의 접두기호(ㄷ/ㅇ/ㅌ/ㅈ)만으로 카테고리를 판별**하면 됨. `총 대회 수/총 역할 수/총 통신문 수/총 지적 수` 열도 이미 집계되어 있어 검증용으로 활용 가능.

### 1학기 — 이미 종료된 학기, 색상 대신 의미 기반으로 판별
1학기 탭은 셀에 2학기처럼 접두기호가 붙어 있지 않고 활동 내용이 문장으로만 적혀 있다. 따라서 Claude Code는 각 활동 텍스트의 **내용을 읽고 의미상 아래 카테고리 중 어디에 해당하는지 스스로 판단**해서 분류해야 한다.

| 카테고리 | 의미 |
|---|---|
| ㅎ | 같은 반 다른 학생에 비해 개별적으로 칭찬받을 만한 행동을 한 경우 (역할과 무관한 개인 행동) |
| ㅇㅎ | 자신이 맡은 역할(반장, 부반장, 각종 도우미 등)에 맞게 그 역할을 잘 수행한 행동 |
| ㄷ | 대회 참가 또는 수상 |
| ㅌ | 가정통신문(정보동의서 등)을 배부 다음날까지 성실히 제출한 경우 |
| 지적 사항 | 아래 키워드 규칙으로 판별(별도) |

**지적 사항 판별 규칙**: 활동 내용 텍스트에 아래 키워드 중 하나라도 포함되어 있으면 "지적 사항"으로 분류하고, 포함되어 있지 않으면 위 표의 카테고리 중 하나로 분류한다.
- `불이행`, `장난`, `지각`, `욕설`, `잡담`

(참고: 실제 시트에서 확인된 지적 사항 예시 — `3/25 자습 불이행`, `6.18 문 장난`, `미인정 지각`, `잦은 욕설로 인한 성장일지`, `6.4 수업태도 제보 (잡담)` 등이 이 규칙에 해당함)

이 규칙 덕분에 셀 배경색을 읽지 못하는 현재 Google Drive 연동 상태로도 1학기 자료 처리가 가능하다 (별도 Apps Script 보조 작업 불필요).

## 3. 파이프라인

### 0단계 — 세션 시작 확인
1. 이번 세션이 처리할 "월"을 사용자에게 확인.
2. 이전 달에 참고했던 원자료는 이번 세션에서 다시 불러오지 않는다(세션 간 컨텍스트 격리).

### 1단계 — 원자료 읽기
- Google Drive 연동으로 대상 문서의 **지정된 탭만** 읽는다 (1절의 개인정보 보호 지침 준수).
- 2학기: 텍스트 접두기호(ㄷ/ㅇ/ㅌ/ㅈ)로 카테고리 분류, "독서로" 문자열 포함 여부로 민트색의 두 의미 구분.
- 1학기: 접두기호가 없으므로 활동 텍스트 의미를 읽고 ㅎ/ㅇㅎ/ㄷ/ㅌ 중 하나로 분류하되, 지적 사항 키워드(`불이행`/`장난`/`지각`/`욕설`/`잡담`)에 해당하면 우선 지적 사항으로 분류.
- 학번 기준으로 학생별 레코드 취합.

### 2단계 — 학생별 문구 생성
- 각 학생의 그 달 분류된 기록(수상·역할·가정통신문/독서록·지적사항)을 바탕으로 서술.
- **활동·상장·대회의 구체적인 명칭은 절대 언급하지 않는다.** 대신 그러한 활동에 적극적으로 참여하는 데서 드러나는 그 학생의 성격·성향(예: 성실함, 책임감, 적극성, 협동심 등)을 중심으로 서술한다. "무엇을 했는지"가 아니라 "그것을 통해 드러나는 학생의 특성"을 적는다.
- 바이트 제한: UTF-8 기준 450바이트 이내(작성 후 반드시 바이트 수 계산해 검증).
- 같은 배치(같은 달 처리 대상 학생 전체) 내에서 학생 간 문장 유사도가 30%를 넘지 않도록 각기 다른 표현·구조로 작성. 특정 문구를 템플릿처럼 복사해 학번만 바꾸는 방식 금지.
- 지적 사항은 성장 가능성이나 개선 노력이 드러나는 방향으로 서술하되, 사실을 왜곡하지 않는다.
- 1학기 자료처럼 항목 구분이 없는 경우, 잘한 일/지적 내용을 문맥상 자연스럽게 하나의 문단으로 통합해 서술.

### 3단계 — 승인 및 저장
1. 학생별 생성 문구와 바이트 수를 사용자에게 표로 제시.
2. 사용자 확인 대기. 수정 요청 시 반영 후 재제시.
3. 사용자가 정확히 "승인함"이라고 답하기 전에는 저장하지 않고, 세션도 종료하지 않는다.
4. "승인함" 확인 후:
   - Drive 폴더 ID `139FiKeKx-diK3oXEofnBEguYnyZ3y-X7`에 저장한다.
   - 엑셀(.xlsx) 업로드가 아니라 **구글 스프레드시트를 새로 생성**하여 저장한다. 파일명에 실행한 "월"을 포함한다 (예: `1학년7반_행동특성및종합의견_9월`).
   - 매 세션(매월)마다 그 달 자료를 담은 새 구글 스프레드시트 파일을 위 폴더 안에 생성하는 방식으로 누적한다.

### 4단계 — 12월 초 종합의견 작성 (연 1회)
1. 그동안 누적 저장된 월별 자료(1학기+2학기 전체)를 모두 불러온다.
2. 학생별로 전체 기간 자료를 종합해 하나의 최종 "행동특성 및 종합의견" 문구 작성.
3. 바이트 제한: 450바이트 이내(동일 검증).
4. 유사도 규칙(같은 배치 내 30% 미만) 동일 적용.
5. 동일하게 사용자에게 제시 → "승인함" 확인 → Drive 폴더 ID `139FiKeKx-diK3oXEofnBEguYnyZ3y-X7`에 새 구글 스프레드시트로 저장 (예: `1학년7반_행동특성및종합의견_최종`).

## 4. 제약 조건 요약
- 바이트 제한: 월별 개별 의견 450바이트 이내, 12월 종합의견도 450바이트 이내.
- 문구 유사도: 같은 배치 내 학생 간 30% 미만.
- 학번 기준 식별.
- 저장은 반드시 사용자 승인 후에만 진행하며, "승인함"이라는 명시적 응답 없이는 세션을 종료하지 않는다.
- 월별 세션은 이전 달 원자료를 다시 참고하지 않는다.
- 대상 문서 내 지정된 탭 외에는 절대 열람·처리하지 않는다 (개인정보 보호).
- 저장 파일 형식: 구글 스프레드시트(매월 새 파일 생성), Drive 폴더 ID `139FiKeKx-diK3oXEofnBEguYnyZ3y-X7`에 저장.

## 5. 사용량 최적화 원칙 (모든 단계 공통 — 반드시 준수)
- 대상 탭 외 다른 탭·범위는 절대 읽지 않는다(1절 개인정보 지침과도 연결). 문서 전체를 통째로 불러오는 방식 대신, 필요한 범위만 최소로 조회한다.
- 이전 달 원자료·이전 세션 대화 맥락은 다시 불러오지 않는다(0단계 규칙과 동일). 매 세션은 그 달에 필요한 자료만 새로 읽는다.
- 같은 자료를 여러 번 반복해서 재조회하지 않는다. 한 세션 안에서 한 번 읽은 데이터는 재사용하고, 중간 결과(분류된 학생별 기록)를 재활용해 문구를 생성한다.
- 학생별 문구 생성·검토는 불필요하게 여러 차례 다시 쓰지 않도록, 바이트 제한(450바이트)과 유사도 조건(30% 미만)을 처음부터 고려해 한 번에 작성하는 것을 목표로 한다. 승인 단계에서 수정 요청이 있을 때만 해당 학생 문구만 다시 작성한다(전체 재작성 금지).
- 저장 시에도 최소 호출로 처리한다(예: 학생별로 각각 파일을 만들거나 여러 번 나눠 쓰지 않고, 한 번에 하나의 구글 스프레드시트로 묶어 저장).
- 위 원칙들은 세션의 각 단계(0~4단계) 전체에 적용되며, 새로운 하위 작업을 설계할 때도 이 원칙을 우선적으로 고려한다.
